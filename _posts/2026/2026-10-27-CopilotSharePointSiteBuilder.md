# SharePoint 사이트도 Copilot과 설계부터: 만들기 전에 계획을 검토하세요

새 프로젝트를 시작할 때 SharePoint 사이트를 만드는 일은 단순히 빈 공간 하나를 여는 작업이 아닙니다. 어떤 목적으로 운영할지, 구성원들이 무엇을 찾을지부터 정리해야 합니다.

Microsoft 365 Roadmap의 **SharePoint Site Builder(RM576708)**는 이 과정에 Copilot을 연결합니다. 핵심은 생성 버튼을 대신 누르는 것보다 **사이트를 만들기 전에 사용자가 명확한 사이트 계획을 검토하고 확인한다**는 데 있습니다.

---

## 새로운 점: 계획을 확인한 뒤 사이트 생성

원문이 설명하는 흐름은 간단합니다. Copilot을 이용해 새 SharePoint 사이트를 만들고, 실제 생성에 앞서 제시된 사이트 계획을 사용자가 검토·확정합니다.

따라서 “일단 만들어 놓고 수정하기”보다는 “무엇을 만들지 먼저 합의하기”에 가까운 경험입니다. 다만 로드맵 설명만으로 자동 구성되는 페이지·라이브러리·권한의 구체적인 범위를 확정할 수는 없습니다.

## 제공 일정과 대상

| 구분 | 원문에 표시된 내용 |
|---|---|
| 플랫폼 | Web |
| 대상 클라우드 | Worldwide, Standard Multi-Tenant |
| 프리뷰 목표 | 2026년 10월 |
| 일반 공급 목표 | 2026년 12월 |
| 수집 시점 상태 | In development |

위 날짜는 로드맵의 목표 일정입니다. 프리뷰 월이 도래했다는 사실만으로 모든 테넌트에서 사용할 수 있다고 해석해서는 안 됩니다.

## 도입 담당자가 준비할 체크포인트

다음은 발표된 세부 기능이 아니라, 조직에서 시험할 때 권장하는 확인 항목입니다.

- 생성 전에 확인할 사이트 목적과 운영 책임자를 정합니다.
- 제안된 계획이 조직의 정보 구조와 맞는지 검토합니다.
- 생성 결과의 공유 범위와 민감한 자료의 보관 위치를 별도로 확인합니다.
- 기존 사이트 생성 정책·승인 절차와 충돌하지 않는지 점검합니다.

사이트 생성에 AI를 붙여도 정보 관리 책임까지 자동으로 해결되지는 않습니다. 계획 검토 단계를 조직의 가이드라인과 연결하는 것이 중요합니다.

## 마무리

SharePoint Site Builder의 주목할 점은 **생성 전 검토**입니다. 실제 제공 범위와 라이선스 조건은 배포 시점의 공식 안내를 확인하고, 먼저 제한된 팀에서 사이트 계획의 품질을 검증하는 접근이 좋겠습니다.

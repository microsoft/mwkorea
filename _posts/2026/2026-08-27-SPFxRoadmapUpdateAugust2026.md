# SPFx가 Copilot 캔버스로 들어갑니다: Copilot Components 공개 미리 보기와 React 18 지원

Copilot에게 무언가를 물으면 텍스트로 답이 옵니다. 유용하지만 한계도 분명합니다. 결재를 올리거나, 폼을 채우거나, 업무 데이터를 표로 훑어보려면 결국 다른 앱을 열어야 하죠.

**Copilot Components**는 이 지점을 겨냥합니다. 여러분이 이미 갖고 있는 **SPFx 기술과 도구, 그동안의 투자**를 그대로 활용해 **Copilot 캔버스 위에 직접 렌더링되는 UI**를 만들 수 있게 합니다. 카드, 폼, 액션, 업무 데이터를 대화 안으로 가져오는 것입니다.

Microsoft 365 Developer Blog의 2026년 8월 SPFx 로드맵 업데이트는 이 기능의 공개 미리 보기가 **전 세계 모든 테넌트에 열렸다**는 소식과, 오래 기다려 온 **React 18 지원 확정**을 함께 전합니다.

---

## 이름이 바뀌었습니다

6월 발표를 따라오신 분이라면 이 기능을 **SharePoint Copilot Apps**로 알고 계실 겁니다. 그건 공개 미리 보기용 작업 명칭이었고, 앞으로 쓰일 가능성이 가장 높은 이름은 **Copilot Components**입니다. 블로그 글, 템플릿, 샘플에서 모두 이 이름을 사용합니다.

다만 원문은 **정식 출시 전까지 명칭을 확정하는 작업이 진행 중이므로 최종이 아니라고** 명시합니다. 이름이 바뀌어도 기능 자체는 달라지지 않으며, GA 전에 최종 명칭을 확정해 알리겠다고 합니다.

---

## Copilot Components란 무엇인가

### 렌더링 방식

컴포넌트는 두 가지 모드로 표시됩니다.

- **인라인(inline)** — Copilot 대화 안에서 빠른 맥락 내 상호작용
- **전체 화면(full-screen)** — 시나리오에 더 넓은 공간이 필요할 때

![인라인과 전체 화면 렌더링 모드](/mwkorea/assets/images/2026-08-27-SPFxRoadmapUpdateAugust2026/image1.webp)

### 알아 둘 세 가지

원문은 Copilot Components가 어떻게 만들어지는지에 대해 세 가지를 강조합니다.

**1. 독자 모델이 아닌 업계 표준 기반**

**React와 표준 JavaScript 라이브러리**로 만들고 **MCP Apps**를 통해 연결합니다. 팀이 React를 안다면 **오늘 바로 만들 수 있습니다.**

**2. 여러분의 테넌트에서 실행됩니다**

컴포넌트는 이미 운영·거버넌스하고 있는 **SPFx 호스팅 모델 위에 여러분의 Microsoft 365 테넌트로 배포**됩니다. 기존 테넌트 경계 안에서 동작하며, **새로 운영할 인프라도 데이터가 놓일 새로운 장소도 없습니다.**

**3. 테넌트 간 이동이 가능합니다**

컴포넌트는 표준 SPFx 솔루션 패키지입니다. 한 번 만들어 자기 테넌트에 배포하거나 여러 고객 테넌트에 배포할 수 있습니다. **SPFx에서 익숙한 크로스 테넌트 스토리가 Copilot 캔버스로 옮겨온 것**입니다.

---

## 미리 보기는 모두에게 열려 있습니다

원문이 특히 구체적으로 밝힌 부분입니다. 가능한 많은 분이 시도해 보고 의견을 주기를 바란다고 강조합니다.

- **전 세계 모든 고객에게 활성화되어 있습니다.** 모든 테넌트에서 켜져 있으며, **특별한 테넌트·링·가입·허용 목록이 필요 없습니다.**
- **Copilot 라이선스가 필요 없고**, 미리 보기 기간에는 **소비 기반 비용(consumption-based costs)도 없습니다.**
- **제공되는 시나리오 샘플로 바로 테스트**할 수 있습니다. 샘플에는 솔루션, 데모 데이터, 설정 안내가 포함됩니다.
- **GA 시점의 라이선스·비용 모델은 곧 확정해 공유**하겠다고 합니다.

## 새 미리 보기 프로그램 참여자를 모집합니다

먼저 오해가 없도록 원문이 분명히 하는 점이 있습니다. **Copilot Components를 쓰기 위해 어디에 가입할 필요는 없습니다.** 기능은 오늘 이미 모든 고객·파트너 테넌트에서 사용 가능하고, Microsoft 365 Copilot 라이선스도 소비 기반 비용도 필요 없습니다. 샘플을 내려받아 바로 시작하면 됩니다.

이번 프로그램은 그것과 다른 것입니다. **소수의 고객·파트너**를 대상으로, 샘플을 넘어 **자사의 실제 업무 프로세스**에 Copilot Components를 적용한 에이전트를 **엔지니어링·제품 팀과 함께 직접 만드는** 밀착 협업입니다.

선정되면 다음을 함께 진행합니다.

- Copilot Components가 가장 큰 가치를 더할 업무 프로세스와 시나리오 식별
- 에이전트와 컴포넌트 설계·구축 지원
- 질문과 이슈에 대한 **엔지니어링 팀 직통 채널** 제공
- GA 이전 로드맵에 의견 직접 반영

![미리 보기 프로그램 신청](/mwkorea/assets/images/2026-08-27-SPFxRoadmapUpdateAugust2026/image2.webp)

**신청 링크: [https://aka.ms/spfx/copilot/preview/signup/](https://aka.ms/spfx/copilot/preview/signup/)**

Microsoft 측의 실무 투입이 필요한 작업이라 **참여 인원은 소수로 제한**됩니다. 이번 회차에 포함되지 못하더라도 기능은 이미 테넌트에 있고 샘플은 공개되어 있으며, GitHub와 커뮤니티 콜을 통한 피드백은 같은 팀에 전달됩니다.

## React 18 지원이 SPFx 1.24에 들어갑니다

오랫동안 커뮤니티 요청 1순위였던 항목입니다. 원문도 **"늦어진 것을 알고 있다"** 고 인정하며, **React 18 지원이 SharePoint Framework 1.24에 들어간다**고 확정했습니다.

GitHub, 커뮤니티 콜, 모든 피드백 설문에서 추적한 **가장 많이 요청된 단일 항목**이었다고 합니다. 여기까지 오려면 기본 제공 웹 파트를 먼저 React 18로 올려야 했고, 그 작업이 1.24를 확약할 만큼 진행됐다는 설명입니다.

### 지금 바로 테스트할 수 있습니다

GA를 기다릴 필요가 없습니다. **Copilot Component React 템플릿은 이미 React 18로 업데이트**되어 있어, SPFx 1.24 Beta 3로 지금 바로 개발해 볼 수 있습니다.

Microsoft가 특히 궁금해하는 피드백 영역은 다음과 같습니다. ([이슈 목록](https://aka.ms/spfx/issues)으로 제보)

- **React 18의 더 엄격한 렌더링 동작**에서 다르게 동작하는 부분
- 기존 솔루션 업그레이드 시 마주치는 **빌드·번들링·타입 정의 문제**
- **React 18과 아직 잘 맞지 않는 서드파티 컴포넌트 라이브러리**

## 로드맵

분기 중심의 예측 가능한 릴리스 주기로 계속 발전시켜 나가겠다고 합니다.

![SPFx 로드맵 2026년 8월](/mwkorea/assets/images/2026-08-27-SPFxRoadmapUpdateAugust2026/image3.webp)

### 버전 1.23.2 — 2026년 6월 (출시 완료)

- 이슈 수정 및 플랫폼 품질 개선
- 목록·라이브러리의 신규·편집 패널 재정의 지원 준비
- 신규 npm audit 취약점 대응

### 버전 1.24 Beta 3 — 2026년 8월 (출시 완료)

- Copilot Components 공개 미리 보기 업데이트
- **SPFx 솔루션의 React 18 지원**
- 이전 베타에서 발견된 Copilot Components 관련 사항 대응
- 신규 npm audit 취약점 대응

### 버전 1.24 정식 출시(GA) — 2026년 10월

- **Copilot Components 정식 출시**
- SPFx 솔루션의 React 18 지원
- 신규 npm audit 취약점 대응

### 버전 1.25 — 2026년 12월 / 2027년 1월

- Copilot Components 모델 추가 발전
- **SPFx CLI 정식 출시(GA)** — 업데이트된 오픈소스 템플릿 포함, **이 버전부터 Yeoman generator를 대체**
- **내비게이션 커스터마이저** — SPFx 컴포넌트로 내비게이션 노드·경험을 재정의하는 옵션 (세부 사항 진행 중)
- 고객·파트너 피드백 기반의 기타 영역
- 신규 npm audit 취약점 대응

> 로드맵 항목은 현재 계획이며 개발 진행과 고객 피드백 반영에 따라 변경될 수 있습니다.

## 우선 검토 중인 사항 (Top of mind)

Microsoft가 가능한 빨리 다루려는 항목으로 두 가지를 꼽았습니다.

- **GA 시점 Copilot Components의 라이선스·비용 모델** — 확정되는 대로 공유
- **React 18 업그레이드 가이드** — 솔루션이 1.24로 이동함에 따라 일반적인 업그레이드 경로와 알려진 서드파티 라이브러리 고려 사항을 정리해 발행 예정

## 한국 개발자·도입 담당자를 위한 체크포인트

- **지금 바로 시도 가능**: 별도 신청이나 라이선스 없이 **모든 테넌트에서 이미 활성화**되어 있습니다. "우리도 대상인가?"를 확인할 필요가 없다는 점이 이번 미리 보기의 특징입니다.
- **비용 확인은 GA 시점**: 미리 보기 중에는 소비 기반 비용이 없지만, **GA 시점의 비용 모델은 아직 미확정**입니다. 프로덕션 도입 계획을 세울 때는 이 발표를 기다려야 합니다.
- **React 18 마이그레이션 준비**: 기존 SPFx 솔루션이 많은 조직이라면 **1.24 GA(2026년 10월) 전에 React 18 호환성 점검**을 시작하는 것이 좋습니다. 특히 서드파티 라이브러리 의존도가 높다면 미리 확인이 필요합니다.
- **Yeoman generator 대체 일정 인지**: **1.25(2026년 12월~2027년 1월)부터 SPFx CLI가 Yeoman generator를 대체**합니다. 사내 개발 가이드나 자동화 스크립트가 Yeoman 기반이라면 전환 계획이 필요합니다.
- **테넌트 경계 유지가 강점**: 컴포넌트가 **자사 테넌트 안에서 실행**되고 새로운 데이터 저장 위치가 생기지 않는다는 점은, 데이터 반출에 민감한 국내 조직에 설득력 있는 지점입니다.
- **파트너에게는 기회**: 표준 SPFx 솔루션 패키지라 **여러 고객 테넌트에 배포**할 수 있습니다. SI·파트너사라면 Copilot 캔버스용 솔루션을 제품화하는 경로가 열린 셈입니다.
- **미리 보기 프로그램 지원 검토**: 구체적인 업무 프로세스 시나리오가 있다면 신청해 볼 만합니다. 선정은 소수지만, **시나리오를 정리해 두는 것 자체가 GA 대비 준비**가 됩니다.

---

## 마무리

원문의 표현을 빌리면 이번 변화의 핵심은 **"텍스트만 있는 답변 대신 실제 UI를 대화 안으로"** 가져오는 것입니다. 그리고 그 UI를 만드는 방법이 새로운 무언가가 아니라 **이미 갖고 있는 SPFx와 React 기술**이라는 점이 실무적으로 중요합니다.

전 세계 모든 테넌트에서 라이선스 없이 열려 있으니, 진입 장벽은 사실상 샘플을 내려받는 것뿐입니다. 정식 출시 목표는 **2026년 10월**이고, 그 전까지의 피드백이 GA 형태를 결정합니다.

다음 로드맵 업데이트는 1.24 GA에 가까워지는 **9월 말**에 예정되어 있습니다.

# 잠재 고객 발굴을 맡는 Sales Development Agent: 프리뷰와 GA 일정을 구분하세요

영업 초기 단계에는 잠재 고객을 조사하고, 적합성을 판단하고, 접촉을 이어 가는 반복 업무가 있습니다. Microsoft는 이 영역을 담당하는 **Sales Development Agent**를 Microsoft 365 Roadmap에서 소개했습니다.

항목 제목에는 “is now available”이 들어가지만, 상세 정보의 상태와 제공 시점은 별도로 확인해야 합니다. 이번 글은 짧은 로드맵 공지에 근거한 소개이며, 실제 도입 조건 전체가 공개됐다고 해석하지 않습니다.

---

## 에이전트가 지향하는 역할

원문 설명은 잠재 고객을 **조사(research), 자격 평가(qualify), 접촉(engage)**하는 자율 에이전트라고 정리합니다. 영업 활동의 처리 역량을 24시간, 주 7일로 확장한다는 방향을 제시합니다.

이는 제품의 지향점이지 매출 상승률, 응답률, 특정 고객 수를 보장하는 성과 수치는 아닙니다. 국내 영업 조직은 담당자의 후속 대응과 에이전트가 수행할 반복 업무를 어떻게 나눌지 검토하는 출발점으로 볼 수 있습니다.

## 제목보다 상세 일정을 확인하세요

| 항목 | 로드맵 기재 내용 |
|---|---|
| Roadmap ID | 573700 |
| 상태 | In development |
| 플랫폼 | Web |
| 클라우드 | Worldwide (Standard Multi-Tenant) |
| Preview | 2026년 10월 |
| General Availability | 2027년 1월 |

따라서 **제목만 보고 2026년 10월에 GA가 완료됐다고 판단하면 안 됩니다.** 로드맵상 프리뷰와 일반 제공 계획을 구분하고, 실제 테넌트의 접근 가능 여부는 제품 문서에서 확인해야 합니다.

## 도입 검토에서 아직 확인해야 할 것

공지에는 세부 라이선스, 가격, 지원 언어, 국가별 제공 범위, CRM 연동 조건, 외부 발신 승인 방식이 설명돼 있지 않습니다. 해당 항목을 지원한다고 가정하지 말고, 원문이 연결하는 [Sales Development Agent 문서](https://aka.ms/SDA-Public-Docs)에서 도입 시점의 조건을 확인하세요.

특히 잠재 고객 접촉을 자동화하려는 조직은 고객 데이터의 이용 목적, 연락 정책, 담당자의 감독 범위를 사전에 정해야 합니다. 이는 로드맵에 새 규정으로 명시된 사항이 아니라 도입 검토 시의 운영 관점입니다.

## 마무리

Sales Development Agent는 Copilot의 활용 범위를 개인 생산성에서 영업 초기 프로세스로 확장하는 사례입니다. 현재 공지로 확인되는 기능 방향과 일정까지만 받아들이고, 구매나 운영 결정은 구체적인 제품 조건과 실제 제공 상태를 확인한 뒤 진행하는 것이 좋습니다.

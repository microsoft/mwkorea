# 에이전트가 늘어날수록 필요한 통제: Work IQ 정책 거버넌스 예고

부서마다 에이전트를 만들기 시작하면 IT의 질문도 달라집니다. “어떻게 만들까?”뿐 아니라 “어떤 에이전트가 어떤 기능을 사용할 수 있게 할까?”를 조직 차원에서 결정해야 합니다.

Microsoft의 **Work IQ: Agent Policy Governance** 로드맵은 관리자가 에이전트와 에이전트의 기능을 대규모로 관리하도록 정책 기반 통제 수단을 제공한다는 내용입니다. 개별 에이전트 설정을 넘어 일관된 운영 기준을 적용하려는 조직이 주목할 만한 방향입니다.

---

## 발표된 핵심은 정책 기반 통제

원문에서 확인되는 범위는 **관리자에게 에이전트와 그 기능에 대한 정책 기반 거버넌스 수단을 제공한다**는 것입니다.

다만 정책의 종류, 적용 단위, 관리 화면, 예외 처리, 기존 관리 기능과의 연결 방식은 공개 설명에 포함되지 않았습니다. 특정 도구 차단이나 부서별 정책 상속이 이미 지원된다고 확대 해석하지 않는 것이 중요합니다.

## 한국 기업에서 생각해 볼 활용 방향

다음 항목은 출시 기능 목록이 아니라 **정책 설계를 위한 검토 질문**입니다.

| 검토 영역 | 조직에서 먼저 정할 질문 |
|---|---|
| 운영 책임 | 에이전트 소유자와 승인자는 누구인가? |
| 기능 범위 | 조회와 실제 변경 작업을 어떻게 구분할 것인가? |
| 데이터 | 민감한 업무 정보를 다루는 에이전트의 기준은 무엇인가? |
| 예외 | 업무상 예외가 필요할 때 누가 검토하고 기록할 것인가? |
| 수명주기 | 담당자 변경이나 서비스 종료 시 어떻게 정리할 것인가? |

정책 도구를 도입한 뒤 기준을 만드는 것보다, 현재 운영 중인 에이전트와 연결 기능을 먼저 목록화하면 실제 기능 공개 후 적용 범위를 판단하기 쉽습니다.

## 프리뷰와 GA 일정

| 항목 | 원문 로드맵 |
|---|---|
| 상태 | In development |
| 프리뷰 예정 | 2026년 11월 |
| GA 예정 | 2027년 1월 |
| 플랫폼 | Web |
| 클라우드 | Worldwide (Standard Multi-Tenant) |

2026년 10월 20일 확인 기준으로는 **출시 예고**입니다. 실제 테넌트 적용 여부, 필요한 라이선스, 관리자 역할과 설정 절차는 후속 공식 문서에서 확인해야 합니다.

## 도입 체크포인트

관리 정책은 에이전트 개발 지침, 데이터 접근 권한, 내부 승인 절차와 함께 설계해야 합니다. 정책이라는 이름만으로 기존 보안·감사 체계를 대체할 수 있다고 가정해서는 안 됩니다.

프리뷰가 제공되면 소수의 대표 에이전트를 대상으로 정책 적용 전후의 동작과 예외 발생 시 사용자 경험을 확인하는 접근을 권합니다. 이 검증 방법은 도입 제안이지 원문이 지정한 절차는 아닙니다.

## 마무리

에이전트 확산의 다음 과제는 생성 속도만이 아니라 **조직이 허용하는 행동을 일관되게 관리하는 능력**입니다. 이번 로드맵은 그 방향을 보여주지만, 구체적인 통제 항목은 실제 문서와 제공 상태를 확인한 뒤 판단해야 합니다.

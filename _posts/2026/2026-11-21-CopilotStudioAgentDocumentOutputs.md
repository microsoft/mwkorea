# 답변을 넘어 파일까지: Copilot Studio Agent 노드의 문서 생성 워크플로

에이전트가 보고서 내용을 잘 작성해도 업무가 바로 끝나는 것은 아닙니다. 실제 현장에서는 그 결과를 파일로 만들고, 공유 폴더에 저장하거나 메일에 첨부하는 후속 작업이 필요합니다.

Microsoft는 2026년 11월 20일 Message Center 공지 **MC1561859**를 통해 Copilot Studio 워크플로의 **Agent 노드가 생성한 문서를 파일 출력으로 반환**하는 기능을 발표했습니다. 한국 시간 기준 발행일은 11월 21일이며, 공지의 GA 예정일은 **2026년 12월 3일**입니다.

이번 변화의 의미는 에이전트의 산출물이 채팅 답변에 머무르지 않고, 다음 자동화 단계에서 사용할 수 있는 파일이 된다는 데 있습니다.

---

## 어떤 문서를 반환하나요?

공지에 명시된 생성 파일 형식은 **PDF, Word, Excel, PowerPoint, CSV**입니다. 이 목록은 Agent 노드가 반환하는 문서 예시이며, 모든 기존 문서를 완벽하게 편집하거나 모든 파일 형식을 지원한다는 발표는 아닙니다.

사용할 에이전트도 한 가지 방식으로 제한되지 않습니다.

| 에이전트 유형 | 원문에 명시된 지원 |
|---|---|
| 인라인 에이전트 | 워크플로 안에서 사용하는 인라인 에이전트와 연동 |
| 기존 게시 에이전트 | 이미 게시된 에이전트와 연동 |

기존 에이전트를 활용할 수 있다는 점은 생성 로직과 업무별 후속 처리를 분리하는 설계에 도움이 됩니다.

## 파일 출력의 구조가 중요합니다

생성된 파일은 **순서가 있는 파일 출력 목록**으로 나타나며, 각 파일에는 다음 정보가 포함됩니다.

- **name**: 파일 이름
- **content type**: 콘텐츠 유형
- **content**: 파일 콘텐츠

후속 단계에서는 이 출력을 사용할 수 있습니다. 텍스트 답변에서 파일 이름을 추측하는 방식이 아니라, 명시적인 파일 출력을 커넥터로 전달하는 흐름입니다.

## 후속 커넥터로 연결하는 활용 시나리오

원문은 파일을 커넥터에 전달해 **메일로 보내기, SharePoint 또는 OneDrive에 저장하기, 레코드에 첨부하기**가 가능하다고 설명합니다.

예를 들어 한국 기업의 업무에서는 다음과 같은 흐름을 검토할 수 있습니다. 아래는 발표된 기능을 바탕으로 한 활용 구상이며, 원문에 완성된 템플릿으로 제공된 것은 아닙니다.

1. 에이전트가 업무 입력을 바탕으로 보고서나 자료를 생성합니다.
2. Agent 노드의 파일 목록에서 이름·콘텐츠 유형·내용을 가져옵니다.
3. 필요한 검토 단계를 거친 뒤 파일을 저장하거나 전달합니다.

주간 보고서 공유, 고객 미팅 후속 자료, 업무 레코드에 남길 첨부 문서처럼 결과물의 보관 위치가 정해진 업무에 잘 맞습니다.

## 도입 전 확인할 사항

파일 생성과 파일 배포는 구분해서 검증하는 것이 좋습니다. 생성 자체가 성공해도 후속 커넥터의 권한, 저장 위치, 첨부 규칙 때문에 전체 워크플로는 실패할 수 있기 때문입니다.

권장 점검 항목은 생성 결과의 사실성, 파일 열기 가능 여부, 여러 파일의 처리 순서, 파일명 충돌, 목적지 접근 권한, 외부 발송 전 검토입니다. 민감한 자료를 다루는 경우에는 조직의 데이터 보호 정책에 맞게 보관·공유 범위를 정해야 합니다.

공개 공지에는 파일 크기 상한, 지원 템플릿 규격, 구체적인 과금 조건이 설명되어 있지 않습니다. 이 기능이 별도 비용 없이 무제한 제공된다고 해석하지 말고 실제 환경의 문서와 라이선스 조건을 확인해야 합니다.

## 일정과 마무리

공지에 따르면 **2026년 12월 3일 GA 예정**이며, 현시점에 관리자가 취해야 할 필수 조치는 없습니다. 이 글은 발표 당시의 기능과 일정을 소개하며, 현재 모든 테넌트에서 사용할 수 있다고 확정하는 안내는 아닙니다.

Agent 노드의 파일 출력은 에이전트가 만든 결과를 업무 시스템에 연결하는 접점을 넓힙니다. 도입의 핵심은 문서 생성만 시연하는 것이 아니라, 검토·저장·전달까지 이어지는 전체 흐름을 설계하는 것입니다.

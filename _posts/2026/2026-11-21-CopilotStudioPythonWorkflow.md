# Copilot Studio 워크플로에 Python이 들어온다: Code 노드의 활용과 주의사항

업무 자동화를 만들다 보면 커넥터로 데이터를 가져오는 것까지는 쉬운데, 그다음 변환 단계가 복잡해지는 경우가 있습니다. 파일에서 필요한 정보를 추출하거나 여러 형식의 데이터를 정리할 때 기본 표현식만으로는 구현이 어려울 수 있습니다.

Microsoft는 2026년 11월 20일 Message Center 공지 **MC1561862**에서 Copilot Studio 워크플로 안에 Python 실행 단계를 추가하는 **Code 노드**를 발표했습니다. 발행 시각을 한국 시간으로 환산하면 11월 21일이며, 공지에서 예고한 일반 공급(GA) 날짜는 **2026년 12월 1일**입니다.

핵심은 코드를 활용한 처리 범위가 넓어진다는 점입니다. 다만 외부 API 호출에 관한 원문 표현이 서로 충돌하므로, 이를 범용 네트워크 실행 환경으로 해석해서는 안 됩니다.

---

## 새로운 점: 표현식으로 어려운 처리를 Python 단계로

메이커는 워크플로에 Python 실행 단계를 넣어 데이터 변환, 파일 파싱과 형식 변환을 수행할 수 있습니다. 공지는 PDF에서 텍스트를 추출하는 작업과 CSV·XML 등의 파일 처리를 활용 예로 듭니다.

코드 작성 방식은 두 가지입니다.

- 자연어로 원하는 처리를 설명하고 AI가 코드를 생성하도록 합니다.
- 메이커가 코드를 직접 작성하거나 생성된 코드를 편집합니다.

자연어 생성은 구현을 시작하는 방법이지 정확성을 보장하는 장치는 아닙니다. 실제 파일 구조와 업무 규칙에 맞는지는 별도로 확인해야 합니다.

## 실행 환경과 비용: Microsoft 관리형 샌드박스

코드는 **Microsoft가 관리하는 샌드박스 환경**에서 실행되며 **Copilot Credits를 소비**합니다. 따라서 Python 단계가 추가되면 업무 흐름뿐 아니라 사용량과 비용도 함께 검토해야 합니다.

원문에는 지원 라이브러리, 실행 시간 제한, 메모리 제한, 파일 크기 상한과 같은 구체적인 실행 규격이 제시되어 있지 않습니다. 일반 Python 서버에서 가능한 모든 작업을 그대로 수행할 수 있다고 가정하지 않는 것이 좋습니다.

## 외부 API 호출은 가능하다고 단정하지 마세요

공지의 활용 설명에는 커넥터가 없는 API 호출이 언급되지만, 이어지는 제한사항에는 **Code 단계가 외부로 나가는 API 호출을 할 수 없다**고 명시되어 있습니다.

이 두 문장은 같은 공지 안에서도 일치하지 않습니다. 따라서 이번 발표만으로 Code 노드의 직접 외부 API 호출 지원을 확정할 수 없습니다. 도입 설계에서는 외부 통신을 Code 노드의 보장된 기능으로 두지 말고, 해당 환경의 제품 문서와 실제 동작을 확인해야 합니다.

## 개발·도입 체크포인트

한국의 메이커와 개발팀은 다음과 같이 작은 데이터 처리부터 검증하는 접근을 고려할 수 있습니다. 이는 원문에 제시된 필수 절차가 아니라 도입을 위한 권장사항입니다.

1. 기존 표현식이나 커넥터만으로 처리하기 어려운 변환 작업을 하나 선정합니다.
2. 개인정보와 기밀 데이터 대신 검증용 파일로 입출력 형태를 확인합니다.
3. 빈 파일, 누락된 열, 잘못된 인코딩 등 실패 조건을 포함해 코드를 점검합니다.
4. 실행량에 따른 Copilot Credits 소비와 실패 시 후속 단계의 동작을 확인합니다.
5. 외부 연결이 필요한 작업은 Code 단계의 네트워크 제약과 분리해 설계합니다.

## 일정과 마무리

원문은 **2026년 12월 1일 GA 예정**이라고 안내하며, 공지를 읽은 관리자가 지금 취해야 할 필수 조치는 없다고 설명합니다. 이 글은 해당 발표 시점의 내용을 정리한 것이며, 이미 모든 환경에 일반 공급됐다는 의미는 아닙니다.

Code 노드는 Copilot Studio의 자동화에서 데이터 처리 선택지를 확장합니다. 기능의 장점만큼 중요한 것은 샌드박스 제약, 비용, 그리고 원문 안의 외부 API 설명 불일치를 분명히 인식하는 것입니다.

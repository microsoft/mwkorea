AI가 답변을 잘하는 단계를 넘어, 사람과 함께 일하고 스스로 업무를 진전시키는 단계로 들어서고 있습니다. 그렇다면 기업은 무엇을 준비해야 할까요?

Satya Nadella가 Ignite 2026 오프닝 키노트에서 제시한 방향은 **‘프런티어 생태계 구축’**입니다. 더 강력한 AI를 도입하는 데 그치지 않고, 조직의 데이터와 업무를 연결하며, 비용과 성과를 살피고, 신뢰할 수 있는 방식으로 운영하자는 구상입니다.

이 글은 제공받은 한국어 전체 번역 PDF를 바탕으로, 발표의 흐름과 주요 내용을 읽기 쉽게 재구성한 편집본입니다. 발표자의 표현을 그대로 확인하려면 [특집 ① — 한국어 전체 번역]({% post_url ignite/2026-11-18-ignite2026-full-translation %})을 참고하세요.

> **자료 기준:** 제품명, 수치, 출시 상태와 성능 관련 설명은 제공 PDF에 담긴 2026년 11월 17일 발표 기준입니다. 이 글은 별도의 제품 문서 검증이나 출시 일정 업데이트를 포함하지 않습니다.

## 먼저 읽는 핵심 요약

- **Copilot은 업무의 시작점으로 확장됩니다.** 대화, 공동 작업, 코딩, 자율 실행을 하나의 경험으로 연결합니다.
- **Microsoft IQ는 조직의 지능을 자산으로 만듭니다.** Microsoft와 타사 시스템의 데이터를 연결해 에이전트가 비즈니스 맥락을 활용하도록 돕습니다.
- **모델은 업무와 비용에 맞춰 다양해집니다.** 의사결정, 코딩, 보안 등 실제 업무에 맞춘 모델과 시스템의 공동 설계가 강조됐습니다.
- **Agent 365는 관리뿐 아니라 성과까지 다룹니다.** 에이전트의 거버넌스와 보안에 더해, 지출과 비즈니스 가치를 연결합니다.
- **보안·투명성·인프라가 함께 발전합니다.** 에이전트형 보안 시스템과 개방형 표준, 자체 반도체와 VM이 이를 뒷받침합니다.

## 1. Copilot: 질문하는 도구에서 함께 일하는 공간으로

이번 발표는 Copilot을 **‘업무를 위한 새로운 운영체제’**로 설명합니다. Chat, Cowork, Code, Autopilot을 하나로 묶고, 지식 업무와 코딩, 비즈니스 프로세스 사이의 경계를 연결한다는 의미입니다. Office의 풍부한 기능도 이 경험 안에 통합됩니다.

주요 접점은 다음과 같습니다.

| 접점 | 발표에서 설명한 역할 |
| --- | --- |
| Home | 간단한 질문부터 복잡한 다단계 작업까지 시작하는 하나의 진입점 |
| Code | 개인이 맞춤형 SaaS 앱과 대시보드 등을 만드는 경험 |
| Autopilot | 팀이 협업하는 공간에서 24시간, 주 7일 업무를 진전시키는 자율 에이전트 |

이 기반에는 **Work IQ**가 있습니다. 사람과 관계, 문서, 이메일, 회의, 채팅, 프로젝트 등 업무가 이루어지는 맥락을 이해하는 역할입니다. 단순히 질문에 맞는 모델을 고르는 것이 아니라, 적절한 지능을 적절한 맥락과 상호작용 방식에 연결하는 구조입니다.

직무별 확장도 이어집니다. 영업·법무·재무·서비스를 위한 Skills, Connectors, Plugins를 Copilot의 여러 접점에 구성하고, Dynamics 365용 비즈니스 애플리케이션 플러그인과 Salesforce 연결도 발표했습니다.

협업의 방향을 보여주는 이름은 **Copilot Workspaces**입니다. 개인이 자신의 에이전트와 일하는 방식에서, 여러 사람과 각자의 에이전트가 **공유된 맥락과 공동의 목표**를 중심으로 일하는 방식으로 나아갑니다.

## 2. Microsoft IQ: 조직의 지능을 연결하고, 보존하고, 개선하기

Copilot이 업무를 수행하는 접점이라면, Microsoft IQ는 그 아래의 시스템을 **독립적인 플랫폼**으로 제공하려는 구상입니다. 핵심은 조직이 자체 지능을 구축하고, 보존하며, 지속적으로 개선하고 통제하도록 돕는 것입니다.

이를 위해 Fabric, Foundry, Microsoft 365의 데이터와 타사 시스템의 맥락을 통합합니다. 발표에서는 **수백 개의 새로운 커넥터**가 Microsoft IQ에 제공된다고 설명했습니다.

연결된 맥락은 조직 전체에서 공유하고 상속할 수 있는 **비즈니스 플러그인**으로 구현됩니다. 에이전트가 개별 자료만 참고하는 데 머무르지 않고, 실제 비즈니스가 이루어지는 곳의 기업 전체 맥락을 활용하도록 하겠다는 방향입니다.

## 3. 모델: 가장 큰 모델보다, 업무에 맞는 지능과 경제성

모델 발표를 관통하는 기준은 **주어진 업무에 적절한 지능을 가장 경제적으로 연결하는 것**입니다. 모델 하나의 성능만이 아니라 제품, 실행 환경인 하네스, 도구, 모델 시스템을 실제 업무에 맞춰 함께 조정하는 접근이 강조됐습니다.

### 의사결정과 모델 선택의 폭 확대

**Microsoft-Decision-1.1**은 정식 출시됐습니다. 멀티모달 지원과 함께 의사결정 정확도와 응답 속도를 개선했다고 소개됐습니다. 발표 기준 4,000곳 이상의 고객이 사용했으며, Microsoft도 라우팅·데이터 라벨링·개인화·콘텐츠 필터링 등 수백 가지 핵심 업무에 활용하고 있습니다.

Foundry에는 **GPT 6.2와 Meta의 최신 모델들**이 도입된다고 발표했습니다. 자체 **MAI 모델 제품군**은 사전 학습 단계의 컴퓨팅 효율과 배포 단계의 토큰 효율을 높이는 방향으로 설계됐습니다.

또한 **MAI Licensed Weights**를 통해 신뢰할 수 있는 고객이 Frontier Co.를 거쳐 Microsoft AI 모델의 가중치에 접근할 수 있게 한다고 밝혔습니다.

### 코딩과 보안에 특화된 모델

| 모델 | 주요 업무와 특징 |
| --- | --- |
| Code 2 | 프로덕션 코드 작업, 심층 디버깅, 여러 파일에 걸친 기능 구현, 저장소 단위 추론, UI 개발을 위한 플래그십 에이전트형 코딩 모델 |
| Code 2 Flash | 코드 설명, 부분 수정, 일상적인 오류 해결, 빠른 반복 등 속도와 처리량이 중요한 업무에 맞춘 모델 |
| Cyber 2 Flash | 보안 업무를 위해 설계한 모델로, 발표에서는 낮은 작업당 비용과 높은 성능을 강조 |

**Code 2와 Code 2 Flash는 발표 당일부터 GitHub Copilot 모델 선택기와 Copilot Fusion의 일부로 정식 제공**되며, Foundry에서도 사용할 수 있다고 설명했습니다.

보안 영역에서도 모델과 도구를 함께 설계하는 접근을 적용하고 있으며, 발표문은 **Cyber 2를 Perception에 통합**하고 있다고 설명합니다.

## 4. Agent 365: 에이전트를 관리하고, 비용을 성과에 연결하기

에이전트가 늘어날수록 중요한 질문도 바뀝니다. ‘무엇을 할 수 있는가’뿐 아니라 ‘어떻게 관찰하고 통제하며, 얼마의 가치를 만드는가’를 확인해야 합니다.

**Agent 365**는 기존 기업의 거버넌스, ID, 보안, 관리 체계를 에이전트까지 확장하는 **컨트롤 플레인**입니다. 발표 기준으로 이미 5,000만 개가 넘는 에이전트가 있다고 소개됐습니다. 기술 스택의 모든 계층에서 관측 가능성을 확보하는 것이 성공적인 AI 배포의 출발점이라는 설명입니다.

여기에 **Agent 365 Business Analytics**가 추가됩니다. 발표에서는 이를 ‘AI 사용을 위한 ERP 시스템’에 비유했습니다.

- 무엇이 지출을 유발하는지 파악합니다.
- AI 지출을 업무 성과와 연결합니다.
- 다양한 시나리오에서 투자수익률(ROI)을 최적화합니다.

즉, AI 운영을 사용량 확인에서 끝내지 않고 **비용과 비즈니스 가치의 관계를 관리하는 FinOps**로 확장하는 것입니다.

## 5. 보안과 투명성: AI가 무엇을 하는지 독립적으로 검증하기

### Perception: 공격 시뮬레이션부터 복구까지 에이전트 팀으로

**Perception**은 여러 보안 에이전트가 플레이북에 따라 협력하는 에이전트형 보안 시스템입니다. 팀별 역할은 명확합니다.

| 에이전트 팀 | 역할 |
| --- | --- |
| Red Team | 공격 시뮬레이션 |
| Blue Team | 공격 탐지 |
| Green Team | 문제 수정과 복구 |

Playbooks로 여러 에이전트를 팀으로 구성해 복잡한 작업과 자율적인 조치를 실행하되, **통제권은 사용자에게 유지**한다는 점이 강조됐습니다. ID, 클라이언트, 클라우드, 앱, 에이전트의 신호와 실행 수단을 연결해 전체 환경을 보호하는 구조이며, 발표에서는 **Perception의 정식 출시**를 알렸습니다.

### AI Transparency Initiative: 모델의 설명만으로는 충분하지 않다

발표는 모델이 스스로 설명하는 내용이 독립적인 증거는 아니라는 점을 짚었습니다. AI가 무엇을 보고 무엇을 하는지 살피고, 행동을 독립적으로 검증하며, 허용할 행동을 통제할 수 있어야 한다는 것입니다.

이를 위한 **Microsoft AI Transparency Initiative**는 세 방향으로 추진됩니다.

1. **표준 협력 확대:** NIST의 Agent Standards Initiative와 협력해 AI 투명성·보안·거버넌스의 개방형 산업 표준 개발에 기여합니다.
2. **생태계 공동 참여:** 모델과 제공업체에 관계없이 책임성과 독립적 검증, 설계 단계의 안전성을 확보합니다. 발표 기준 40개 조직이 표준 정의와 적용에 참여하고 있습니다.
3. **Microsoft 제품에도 적용:** MAI 모델, Foundry, Copilot을 포함한 자체 제품에 동일한 표준을 적용하기 위해 노력합니다.

## 6. 인프라: 모든 와트와 칩에서 더 많은 성능을

이 모든 서비스와 모델의 기반에는 반도체, 서버, 인프라가 있습니다. Microsoft는 생태계 전반의 혁신을 수용하는 이기종 플랫폼과 자체 하드웨어의 공동 설계를 함께 추진한다고 설명했습니다.

- **Maia 300:** 최근 발표한 칩으로, 주요 GPU 기반 시스템 대비 와트당 40% 더 많은 토큰을 처리할 것이라고 설명했습니다.
- **Azure Boost·Azure Integrated HSM:** 핵심 인프라와 보안 기능을 목적에 맞게 설계한 반도체로 이전합니다.
- **Cobalt 200 VM:** 차세대 VM의 정식 출시를 발표했습니다. Microsoft 범용 VM 중 가장 높은 성능과 업계 최고 수준의 가격 대비 성능을 제공한다고 소개했습니다.

모델뿐 아니라 이를 실행하는 기반까지 함께 최적화해 효율을 높이겠다는 방향입니다.

## 결국 핵심은 사람, 조직의 통제권, 신뢰

이번 키노트의 여러 발표는 하나의 흐름으로 이어집니다. **Copilot이 업무의 접점이 되고, IQ가 조직의 맥락을 연결하며, 모델이 작업을 수행합니다. Agent 365는 이를 관리하고 비용과 성과를 연결하며, 보안·투명성·인프라가 그 기반을 뒷받침합니다.**

이 모든 변화의 기준으로 제시된 것은 세 가지입니다. **인간의 열망을 중심에 두는 것, 조직이 자체 지능과 학습을 통제하는 것, 그리고 신뢰를 확보하는 것**입니다.

‘프런티어 생태계’는 기술의 발전을 사람과 조직, 사회의 실질적인 성과로 전환하겠다는 약속입니다. 이번 발표를 개별 제품 목록보다 하나의 연결된 구조로 읽어야 하는 이유도 여기에 있습니다.
